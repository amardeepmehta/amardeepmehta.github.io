An illustrated, worked technical reference for LLM inference — 21 October 2026.

Reading map

This reference builds the concepts in dependency order: tokens → hidden states → the four learned attention matrices → projection and reshape → head-wise attention → causal masking → KV cache → prefill/decode → GQA → performance implications. Thirteen figures and several dimension-checked examples make each stage traceable. All numerical model dimensions are illustrative configurations, not claims about a specific checkpoint.

One-sentence summary: During autoregressive inference, the current Query selects information from Keys and Values for the current and preceding positions; a KV cache preserves the preceding K/V tensors so that future decode steps need not recompute them.

Tokens, embeddings, and hidden states

What is a 4,096-dimensional token vector?

A tokenizer maps text into token IDs. An embedding lookup converts each token ID into a dense numerical representation. For a decoder with hidden size dmodel=4096d_{model}=4096, each token’s embedding and each layer’s hidden state have 4,096 scalar components. These are learned coordinates, not one named human concept per coordinate.

Imagine the input text “The cat sat” is represented as three tokens for this teaching example. Real tokenizers may split text differently.

A toy four-dimensional version might be:

Token Illustrative vector
The [0.2,−0.5,0.8,0.1][0.2,-0.5,0.8,0.1]
cat [0.9,0.3,−0.2,0.7][0.9,0.3,-0.2,0.7]
sat [−0.1,0.6,0.4,0.3][-0.1,0.6,0.4,0.3]

For the actual 4,096-dimensional example, we write the input hidden states as a matrix with one row per position:

X=[x1x2x3]∈ℝ3×4096.X=\begin{bmatrix}x_1\\x_2\\x_3\end{bmatrix}\in\mathbb{R}^{3\times4096}.

The first layer receives embedding-based representations, while later layers receive the preceding layer’s transformed hidden states. The hidden size is not the number of tokens, the number of attention heads, or the KV-cache size.

The role of attention within one transformer layer

A simplified pre-normalized decoder layer consists of: (1) normalization; (2) linear Q/K/V projections; (3) causal self-attention and output projection; (4) residual addition; (5) a feed-forward network (MLP) with normalization and residual addition. Implementations vary in the ordering and specifics of these suboperations.

Figure 1. Conceptual dataflow of a decoder transformer layer and its per-layer KV cache. Attention answers: “For the current token position, which accessible token positions contain useful information, and how should it be combined?” A Query identifies what the position seeks; Keys determine matching scores; Values contain information that is aggregated. These roles are learned numerical operations, not literal questions and answers.

Q, K, and V are linear projections

For a sequence of hidden states XX, a layer computes:

Q=XWQ,K=XWK,V=XWV.Q=XW_Q,\qquad K=XW_K,\qquad V=XW_V.

The matrices WQ,WK,WVW_Q,W_K,W_V are model parameters learned during training. They are not the KV cache. The projected K and V activations, for actual tokens and positions, become cache entries.

Why reshape the projected tensor into separate heads?

The complete Query projection has 3×40963\times4096 values, but attention is calculated independently for 32 Query heads. After projection:

Q:(3,4096)→reshape(3,32,128).Q:(3,4096)\xrightarrow{\text{reshape}}(3,32,128).

For one token, dimensions 1–128 of its projected Query form head 1; 129–256 form head 2; and so on. Each head’s slice contains 128 values. Corresponding K/V projections reshape as:

K,V:(3,1024)→reshape(3,8,128).K,V:(3,1024)\xrightarrow{\text{reshape}}(3,8,128).

Figure 4. The complete Query vector is partitioned into head-specific slices; GQA uses fewer K and V heads. Why do this? Each Query head must produce its own softmax attention-weight distribution. One 4,096-dimensional attention head would produce just one score matrix/softmax per sequence; 32 independent 128-dimensional heads produce 32 different attention-weight matrices. A later output projection can mix what these heads learn. The projections’ learned columns create different head-specific features; reshape just reorganizes those features. It does not change any scalar values or compress the tensor.

The projection could equivalently be implemented as 32 smaller matrices WQ(h)∈ℝ4096×128W_Q^{(h)}\in\mathbb{R}^{4096\times128}, then stacked. Computing one large XWQXW_Q and reshaping is a convenient equivalent implementation. Attention runtimes commonly transpose to a head-first tensor layout [B,H,S,D][B,H,S,D] for parallel head-wise kernels; this transpose is a layout operation too.

End-to-end attention formula and shapes for GQA

For Query head hh, let g(h)g(h) be its assigned KV head. For zero-indexed heads in this example, g(h)=⌊h/4⌋g(h)=\lfloor h/4\rfloor because 32/8=432/8=4 Query heads share each KV head. Then:

Oh=softmax(QhKg(h)⊤128+M)Vg(h)\boxed{O_h=\operatorname{softmax}\left(\frac{Q_hK_{g(h)}^\top}{\sqrt{128}}+M\right)V_{g(h)}}

All 32 outputs have shape 3×1283\times128. They are concatenated and projected:

Y=Concat(O1,…,O32)WO\boxed{Y=\operatorname{Concat}(O_1,\ldots,O_{32})W_O}

(3,32,128)⏟head outputs→(3,4096)⏟concatenated(4096,4096)⏟WO→(3,4096)⏟Y.\underbrace{(3,32,128)}_{\text{head outputs}}\longrightarrow\underbrace{(3,4096)}_{\text{concatenated}}\;\underbrace{(4096,4096)}_{W_O}\longrightarrow\underbrace{(3,4096)}_{Y}.

Thus the full output has the same model width as the input and can be added to the residual stream. Q/K/V projection, reshape, per-head attention, concatenation, and WOW_O together constitute the attention module; the layer also includes normalization, residual connections, and an MLP.

Scaled dot-product causal attention

For one Query head, the general scaled dot-product attention equation is:

Attention(Q,K,V)=softmax(QK⊤D+M)V\boxed{\operatorname{Attention}(Q,K,V)=\operatorname{softmax}\left(\frac{QK^\top}{\sqrt D}+M\right)V}

Here MM is the causal mask: inaccessible future-token scores receive a sufficiently negative value, mathematically −∞-\infty, before softmax. When considering only keys up to the current position, there are no future positions and the mask may be omitted from the displayed equation. The 1/D1/\sqrt D factor scales dot products; softmax converts each row of scores into attention weights summing to one.

Matrix multiplication for three prompt positions

For one attention head, the matrices have shape Q,K,V∈ℝ3×128Q,K,V\in\mathbb{R}^{3\times128}. Thus:

Q⏟3×128K⊤⏟128×3=QK⊤⏟3×3.\underbrace{Q}_{3\times128}\underbrace{K^\top}_{128\times3}=\underbrace{QK^\top}_{3\times3}.

Expanding the scores:

QK⊤=[Q1K1⊤Q1K2⊤Q1K3⊤Q2K1⊤Q2K2⊤Q2K3⊤Q3K1⊤Q3K2⊤Q3K3⊤].QK^\top=\begin{bmatrix} Q_1K_1^\top & Q_1K_2^\top & Q_1K_3^\top\\ Q_2K_1^\top & Q_2K_2^\top & Q_2K_3^\top\\ Q_3K_1^\top & Q_3K_2^\top & Q_3K_3^\top \end{bmatrix}.

A decoder uses causal attention: Query 1 may attend only to position 1; Query 2 to positions 1–2; Query 3 to positions 1–3.

Derive the single-token equation from the general equation

If we only need token 3 (“sat”), use the third Query row:

O3=softmax(Q3[K1,K2,K3]⊤D)[V1,V2,V3].\boxed{O_3=\operatorname{softmax}\left(\frac{Q_3[K_1,K_2,K_3]^\top}{\sqrt D}\right)[V_1,V_2,V_3].}

The shapes, for one head, are:

Q3⏟1×128[K1,K2,K3]⊤⏟128×3→scores⏟1×3→[V1,V2,V3]⏟3×128→O3⏟1×128.\underbrace{Q_3}_{1\times128}\underbrace{[K_1,K_2,K_3]^\top}_{128\times3} \ \rightarrow\ \underbrace{\text{scores}}_{1\times3} \ \rightarrow\ \underbrace{[V_1,V_2,V_3]}_{3\times128} \ \rightarrow\ \underbrace{O_3}_{1\times128}.

The bracket notation [K1,K2,K3][K_1,K_2,K_3] means the stack of row vectors, not a single concatenated row vector. The earlier general equation and this single-token equation describe the same operation. The latter merely calculates one row of the attention output.

Why causal attention enables a KV cache

The KV cache exists because in a decoder-only causal transformer, appending a new token does not alter hidden states already computed at earlier positions. Previous tokens cannot attend to later ones. Their K/V representations for a given layer therefore stay valid for subsequent steps, provided the model, positional conventions and earlier context remain unchanged.

For token tt, current-head attention needs:

Ot=softmax(Qt[K1,…,Kt]⊤D)[V1,…,Vt].O_t=\operatorname{softmax}\left(\frac{Q_t[K_1,\ldots,K_t]^\top}{\sqrt D}\right)[V_1,\ldots,V_t].

What is reused? K1…Kt−1K_1\ldots K_{t-1} and V1…Vt−1V_1\ldots V_{t-1}.

What is newly calculated? Qt,Kt,VtQ_t,K_t,V_t, based on the current hidden state at that layer. New Kt,VtK_t,V_t are appended to the per-layer cache.

Why is Q not cached? Past Queries Q1…Qt−1Q_1\ldots Q_{t-1} were needed to calculate past outputs. The new output formula has QtQ_t but no past QiQ_i terms. Keeping those Queries would consume memory without helping standard next-token decoding.

Representation Role in attention Keep for future decode?
Past Query QiQ_i Produced the output at past position ii No
Past Key KiK_i Is matched by later Query vectors Yes
Past Value ViV_i Is mixed into later attention outputs Yes

The cache also remains layer-local: layer ℓ\ell has its own projected K(ℓ),V(ℓ)K^{(\ell)},V^{(\ell)} from that layer’s hidden states. A single cache cannot be reused indiscriminately across all layers.

Prefill and decode: a precise timeline

Prefill: The model processes the initial prompt positions together (often with specialized tiled attention kernels). It computes Q/K/V for the prompt in every layer, uses causal attention, and creates the prompt KV cache. The final prompt position’s output logits yield the first generated token.

Decode: The next forward pass consumes that newly generated token as input, forms its Q/K/V in each layer, attends against the cached prompt keys/values plus its own K/V, appends its K/V, and predicts the next token. Repeat for later generated tokens.

Compute consequences

For one head and sequence length SS, conventional full self-attention computes S×SS\times S Query–Key scores during prefill: roughly O(S2D)O(S^2D) attention arithmetic. A single new decode Query compares against SS available Keys: roughly O(SD)O(SD) attention arithmetic for that new token.

These complexities refer to the attention suboperation; projection/MLP work, batching, kernel tiling and the full model have additional costs. A modern FlashAttention-style prefill need not materialize the entire S×SS\times S scores in HBM.

Prefill is often relatively compute-intensive, whereas long-context decode is frequently constrained by repeated reads of model weights and cached KV, especially at relevant batching levels. TTFT (time to first token) contains queueing, prefill and other overheads; TPOT (time per output token) characterizes generation latency after the first token.

KV-cache memory: derive it from first principles

One token, one transformer layer, with HKVH_{KV} KV heads and head dimension DD stores:

  • HKV×DH_{KV}\times D Key elements.
  • HKV×DH_{KV}\times D Value elements.
  • Each element occupies PP bytes.

Thus the logical memory formula is:

MKV=2×L×B×S×HKV×D×P\boxed{M_{KV}=2\times L\times B\times S\times H_{KV}\times D\times P}

where LL is layers, BB is number of sequences of equal cached length, SS is tokens cached per sequence, HKVH_{KV} is KV heads, DD is elements per K/V head, and PP is bytes per element. For unequal sequence lengths, replace B×SB\times S with ∑bSb\sum_b S_b.

Worked example: 32 layers, GQA, 8,192 tokens, BF16

Use L=32L=32, B=1B=1, S=8192S=8192, HKV=8H_{KV}=8, D=128D=128, P=2P=2.

  1. One K head per token per layer: 128×2=256128\times2=256 bytes.
  2. One V head: another 256 bytes.
  3. All eight KV heads: 8×(256+256)=40968\times(256+256)=4096 bytes = 4 KiB per token per layer.
  4. All 32 layers: 32×4 KiB=128 KiB32\times4\text{ KiB}=128\text{ KiB} per token.
  5. At 8,192 cached tokens: 8192×128 KiB=1 GiB8192\times128\text{ KiB}=\boxed{1\text{ GiB}} for one sequence.
  6. At batch size 32, assuming each sequence has 8,192 cached tokens: 32 GiB logical KV data.

The hidden state is 4,096 numerical dimensions. Separately, the computed K/V storage here is 4,096 bytes per token per layer. Those equal-looking numbers refer to different units and their equality is incidental.

Actual allocated memory may differ because of page/block granularity, fragmentation, reservations, sliding-window or other attention variants, concurrency, cache eviction, prefix sharing, replication or distribution across devices. This formula estimates the logical full-history KV tensor payload.

Why shared K/V does not make Query heads identical

Consider a toy D=2D=2 example with shared Keys K1=[1,0]K_1=[1,0], K2=[0,1]K_2=[0,1]. Two Query heads have different vectors QA=[2,0]Q_A=[2,0] and QB=[0,2]Q_B=[0,2]. Their scaled scores are [2,0][\sqrt2,0] and [0,2][0,\sqrt2], respectively. Softmax therefore produces different attention distributions: approximately [0.804, 0.196] and [0.196, 0.804]. Both heads can use the same cached Keys and Values yet output different weighted Value combinations.

Figure 11. Two independent Query heads use one shared KV head but generate different attention weights. For the earlier 32-layer, 8K-token example:

Figure 12. Theoretical logical KV storage for MHA, GQA and MQA under equal layer, head-dimension, context and precision assumptions. - MHA, 32 KV heads: 4 GiB / sequence. - GQA, 8 KV heads: 1 GiB / sequence. - MQA, 1 KV head: 128 MiB / sequence.

These figures are KV storage reductions, not promises of 4× or 32× overall decoding speed. Actual speed is affected by model-weight traffic, attention kernels, bandwidth, batching, compute, quantization and scheduler behavior.

GQA is fundamentally a model architecture and checkpoint parameterization. You cannot simply change HKVH_{KV} of an already trained MHA checkpoint at runtime and expect equivalent outputs. Converting checkpoints requires suitable modification of projections and typically additional adaptation/training; the original GQA paper presents an uptraining recipe.

Why the KV cache influences inference throughput

Benefits of caching: It removes repeated computation of past-token hidden states and their Q/K/V projections on each autoregressive step. It is therefore essential to efficient token-by-token generation.

Its remaining cost: At each step, the current Query still needs attention over accessible past K/V positions, so their representations are repeatedly consumed. Depending on the workload, this results in substantial HBM traffic. Larger contexts and more concurrent sequences mean more live KV data.

What GQA changes: It stores and reads fewer distinct K/V head vectors for a given token history. This improves feasible context/concurrency and may reduce memory-bandwidth pressure during decode. It does not shrink the number of historical positions or eliminate attention arithmetic.

Related methods target different costs:

Technique Primary mechanism What it does not mean
GQA / MQA Fewer distinct K/V heads Not runtime-only lossless compression of arbitrary MHA weights
KV quantization Fewer bytes per K/V element Not fewer token positions by itself
PagedAttention KV cache allocation, paging, and potential block sharing Does not reduce the theoretical number of K/V values in a full-history attention model
FlashAttention Tiled, IO-aware exact attention computation Does not make persistent decode KV storage disappear
Prefix caching Reuse K/V for identical cached prefixes Not automatic reuse for unrelated prefixes

Prefill/decode disaggregation and KV transfer

In a disaggregated design, one accelerator performs prefill while a different accelerator performs subsequent decode. Instead of transferring the prompt Queries or every hidden state, the decode worker generally needs compatible per-layer prompt K/V tensors, together with essential metadata (such as positions, layer/head mapping, data type and layout). The decode worker then computes new Q/K/V tensors for later tokens.

Figure 13. Conceptual handoff of per-layer KV data between prefill and decode runtimes. For the 8K-token example, GQA reduces the logical KV payload from 4 GiB (32 KV heads) to 1 GiB (8 KV heads), provided other parameters are held equal. Real transfer volume and latency may differ due to data distribution across devices, transport framing, paging, dtype conversion, transfer overlap and runtime requirements.

Cross-vendor caveat (e.g., NVIDIA prefill → another accelerator’s decode): Sharing architecture and the name “KV cache” is not enough to guarantee a working handoff. Both runtimes must agree on model weights, layer/head semantics, RoPE positional conventions, KV layout/order, dtype/quantization/scales, and how cache tokens map to physical buffers. Support for actual transfer/import APIs must be established separately.

Practical shape-checking example

The following pseudocode is shape-oriented, not a full implementation (normalization, RoPE, causal masking, fused kernels, residuals and batch axes are omitted):

# One decoder layer; illustrative GQA dimensions
S, d_model, Hq, Hkv, D = 3, 4096, 32, 8, 128
X = hidden_states                 # [S, 4096]
Q = (X @ Wq).reshape(S, Hq, D)    # [3, 32, 128]
K = (X @ Wk).reshape(S, Hkv, D)   # [3,  8, 128]
V = (X @ Wv).reshape(S, Hkv, D)   # [3,  8, 128]

# On prefill: per-head attention with a causal mask; save K, V.
cache_K, cache_V = K, V

# At a later decode step, X_new represents ONE current token.
q_new = (X_new @ Wq).reshape(1, Hq, D)
k_new = (X_new @ Wk).reshape(1, Hkv, D)
v_new = (X_new @ Wv).reshape(1, Hkv, D)
cache_K = append(cache_K, k_new)  # [4, 8, 128]
cache_V = append(cache_V, v_new)  # [4, 8, 128]

# Each q_new head h attends to KV head (h // 4).
# In optimized GQA, shared KV are NOT stored four times.

Eight correctness checks

  1. Q=XWQQ=XW_Q is S×(HQD)S\times(H_QD) in the example, before head reshaping.
  2. One Query head is S×DS\times D after reshaping.
  3. One GQA K/V head is also S×DS\times D, but there are fewer KV heads.
  4. The attention score matrix for one Query head has shape query length × accessible key length.
  5. During causal prefill, future positions are masked.
  6. Decode reuses past K/V, not past Q, and appends new K/V.
  7. Every transformer layer maintains its own KV content.
  8. A fourfold KV-memory reduction is not necessarily a fourfold reduction in TPOT.
